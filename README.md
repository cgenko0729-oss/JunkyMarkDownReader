# Junky Markdown Reader

Typora 风格的 Markdown **阅读器**，Windows 桌面应用。以阅读为主，附带一个源码编辑模式。

正文排版完全交给 Typora 主题 CSS —— 网上下载的任意 Typora 主题都能直接丢进 `themes/` 目录使用。

![应用图标](assets/icon-256.png)

## 快速开始

```bash
npm install          # 安装依赖
npm start            # 启动（开发模式）
npm run dist         # 打包成 Windows 安装程序 → dist/
```

打开指定文件启动：

```bash
npx electron . "路径\到\文档.md"
```

| 源码编辑 | `Ctrl+E` 整篇切换成原始 Markdown（带每行行号），`Ctrl+S` 保存并返回阅读 |
| 混合排版 | 段落保持舒适行宽，表格/代码块/图表自动向两侧突破（见下文） |

| 代码高亮 | highlight.js，配色随亮暗模式切换 |
| Mermaid 图表 | ` ```mermaid ` 代码块渲染成图，按需加载（不拖慢启动） |
| 自动刷新 | 在别的编辑器里改完保存，阅读器立刻刷新且保持滚动位置 |
| 图片 | 相对路径本地图片、网络图片，点击放大 |
| 本地跳转 | 文档里的 `./other.md` 链接在应用内跳转 |
| 拖放 | 拖 `.md` 文件进窗口打开，拖文件夹进窗口设为工作区 |
| 记忆 | 主题、字号、侧栏开合、窗口尺寸、最近打开、各文档滚动位置 |

还支持：GFM 表格、任务列表、脚注、`{.class}` 属性语法。

> **关于行号**：正文是渲染后的 HTML，跟原文没有逐行对应关系，所以行号标的是
> **每个块的起始行**（标题、段落、列表的每一项、表格、代码块、引用各一个号），
> 而不是每一行都有号。行号来自 markdown-it 的 token `.map`，与原文一一对应，
> 拿去跟编辑器对位是准的。

## 换主题

**装新主题**：把任意 Typora 主题的 `.css` 丢进 `themes/` 目录，重启后就出现在工具栏
的主题下拉里。主题若带配套资源（字体等子文件夹），连子文件夹一起放进去。
菜单「帮助 → 打开主题文件夹」可以直接跳过去。

**切换**：工具栏的下拉；亮色模式和暗色模式各自记住用哪个主题。

### 第三方主题的兼容处理

这些主题是给真正的 Typora 写的，DOM 结构跟本应用不完全一样。已经做了三处兼容：

- **`#write` 居中兜底**：Typora 里居中由 `#write` 外层容器负责，很多主题因此不给
  `#write` 写 margin。用零特异性的 `:where(#write)` 兜底 —— 主题自己设了就听主题的。
- **代码块配色自动适配**：实测代码块的背景亮度来决定用亮色还是暗色的 highlight.js
  配色。这样 `drake-jb` 那种「亮色正文 + 暗色代码块」的主题也不会糊成一片。
- **文字色归 hljs、底色归主题**：hljs 样式表排在主题之后，并清掉它自带的背景。

> 仍有一处对不齐：主题里针对 CodeMirror 类名（`.cm-keyword` 等）写的**语法着色**
> 不会生效，语法配色始终来自 highlight.js。硬对齐需要做一层类名映射，不干净。

## 混合排版：宽度怎么分配

段落和表格对宽度的需求完全相反，所以本应用给它们不同的宽度。

**段落有行宽上限。** 中文每行 35～45 字最好读，超过 60 字之后眼睛从行尾回扫到下一行
行首会明显吃力。所以段落不会去填满窗口 —— 哪怕屏幕再宽。

**表格、代码块、Mermaid 图没有这个问题。** 它们跟行宽无关，宽一点是纯收益。所以这三
类元素会自动向左右各突破 200px，把段落两侧的空白换成信息密度。

```
┌────────────────────────────────┬──────┐
│      ┌──────────────────┐      │ 大纲 │
│      │ 段落 42 字/行     │      │      │
│      └──────────────────┘      │      │
│   ┌───────────────────────────┐│      │
│   │ 表格 / 代码块 各突破 200px ││      │
│   └───────────────────────────┘│      │
└────────────────────────────────┴──────┘
```

段落宽度自己按文档类型调：`Ctrl+Shift+←/→` 在 8 档之间切换（跟随主题 / 700 / 780 /
860 / 960 / 1080 / 1220 / 1400），选择会记住。用**固定像素**而不是百分比，所以开关
侧栏时段落宽度不会跳动。

两个例外要知道：

- **嵌套的宽元素不突破。** 列表项或引用块里的代码块会老实待在缩进里 —— 突破会破坏
  缩进层次，让人看不出它属于哪一层。
- **窗口太窄时宽元素会自动收一点。** 这是防溢出保护，避免它们捅出正文区产生水平
  滚动条。只在空间真的不够时触发。

## 架构

```
主进程                                    渲染进程
─────────────────────────────────        ─────────────────────────────
markdown.js   markdown-it + 插件          app.js         主控制器
              + highlight.js              sanitize.js    DOMPurify 清洗
              → HTML 字符串 ──── IPC ──→  theme.js       主题/亮暗切换
                                          outline.js     大纲 + 滚动高亮
file-service  读文件/列目录/chokidar       filetree.js    文件树
              + 保 BOM/换行符的写回        search.js      文档内查找（Ctrl+F）
protocols.js  app:// 与 md-asset://       linenum.js     源文件行号槽
store.js      设置持久化                   editor.js      源码编辑模式（Ctrl+E）
                                          mermaid-render 按需加载图表
```

三个关键设计决定（详细理由见 [PLAN.md](PLAN.md)）：

1. **Markdown 渲染放在主进程。** 渲染进程只收 HTML 字符串，因此完全不需要在浏览器
   环境里加载 npm 包 —— 绕开了 ESM / bare specifier 那一堆麻烦。
2. **界面走 `app://` 协议而不是 `file://`。** `file://` 页面的同源策略特殊，CSP 里
   的 `'self'` 在那里行为不可预期。换成标准协议后 CSP 完全正常。
3. **双层样式体系。** `#write` 内部完全交给 Typora 主题；工具栏和侧栏用 `shell.css`
   自己的一套 CSS 变量。外壳里每个元素都显式声明 `background`/`color`，否则会被主题
   的 `body` 规则带跑。

## 安全

打开一份来源不明的 `.md` 不应该有风险。三道措施：

1. 渲染进程 `contextIsolation: true` + `sandbox: true` + `nodeIntegration: false`，
   拿不到任何 Node API。
2. 渲染结果一律过 DOMPurify：`<script>`、`on*` 事件属性、`javascript:` 链接、
   `<iframe>`、`<style>`、表单控件全部剥掉（任务列表的 checkbox 除外）。
3. 本地资源走 `md-asset://` 协议且有**目录白名单** —— 只有当前文档所在目录和工作区
   目录下的文件读得到，文档没办法读你硬盘上任意位置的文件。

CSP 为 `default-src 'none'` 起步逐项放行，`script-src 'self'` 意味着文档里夹带的脚本
即使漏过清洗也执行不了。

## 已知限制

- **编辑只有源码模式。** 不做所见即所得 —— 那需要 HTML→Markdown 的反向转换（有损），
  而且会同时和 Typora 主题 CSS、搜索高亮 Range、行号槽三者打架。
- **编辑模式没有语法着色。** 用的是原生 textarea：0 新依赖、0 启动开销，
  中文输入法也绝不会出问题。
- **跨保存没有撤销。** 编辑框内 `Ctrl+Z` 是原生的，存盘之后就回不去了。
- **没有数学公式。** 需要的话在 `src/main/markdown.js` 里挂 `markdown-it-texmath` +
  KaTeX 即可，渲染管线留了位置。
- **查找只在当前文档内。** 跨文件夹的全文搜索没做。
- **没有导出 PDF。** 用 Electron 的 `webContents.printToPDF()` 成本很低，想加随时能加。
- **行号是块级的**，不是每行都有 —— 渲染视图里做不到逐行对应（见上文「关于行号」）。
- **超大文件（>1MB）会卡几秒。** 一次性渲染，没做分块或虚拟滚动。
- **代码块配色不跟随 Typora 主题**（见上文「换主题」一节的说明）。
- 安装包没有代码签名，Windows 首次运行会弹 SmartScreen 提示。
